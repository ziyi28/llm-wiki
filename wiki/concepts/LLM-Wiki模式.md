# LLM Wiki 模式

用 LLM 构建个人知识库的一种模式：LLM 不是在查询时临时检索原始文档（对比 [[RAG]]），而是**增量地构建并维护一个持久的 wiki**——一组结构化、互链的 markdown 页面，位于用户与原始资料之间。

## 与 RAG 的关键区别

| | [[RAG]] | LLM Wiki |
|---|---|---|
| 知识形态 | 原始文档 + 检索索引 | 持续维护的互链页面 |
| 综合发生在 | 每次查询时，从头再来 | ingest 时编译一次，之后保持最新 |
| 积累 | 无 | **复利**：交叉引用已就位、矛盾已标注、综合已含全部所读 |

## 运作方式

- 结构上分三层：见 [[三层架构]]。
- 日常只有三种操作：[[Ingest]]、[[Query]]、[[Lint]]。
- 导航依赖两个特殊文件：见 [[索引与日志]]。
- 用户几乎从不亲手写 wiki——LLM 写，用户在 [[Obsidian]] 里实时浏览。原文的比喻：**Obsidian 是 IDE，LLM 是程序员，wiki 是代码库**。

## 为什么有效

知识库难以为继的从来不是阅读和思考，而是**簿记**——更新交叉引用、保持摘要最新、标注矛盾、维持几十个页面的一致性。人会烦、会忘，维护负担增长快于价值，所以人类 wiki 常被荒废。LLM 不会腻烦、不漏更新、一次能改十几个文件，维护成本趋近于零。

## 渊源

与 [[Memex]]（1945）一脉相承：私人、主动策展、文档间的关联与文档本身同样有价值。Bush 未能解决的维护者问题，由 LLM 承担。
